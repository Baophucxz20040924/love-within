# Realtime transport

`GET /api/realtime?space=couple|friends` accepts a Bearer access token, verifies the account exists, and requires friends-space membership for `friends`. Unpaired accounts may subscribe to `couple`. The stream registers before emitting `ready`; every frame is `event: ready|dirty|access` and `data: {"version":1,"domains":[...]}` with no actor, content, or entity ID. A `: heartbeat` comment is sent every 20 seconds. Hints are not durable and REST remains authoritative; ready/reconnect/resume must resync. Clients must retain polling as a fallback. `access` requires client-side revocation handling, not just an ordinary stale mark. An `access` frame with an empty domains list revokes the whole current scope and takes precedence over coalesced domain hints.

A connection ends by the earlier of verified JWT exp, iat plus access maxAge, or ten minutes. There is no new session-revocation mechanism. Limits are 2,000 connections per process, 10 per account and 5 per account/space; limit failures return 429 and Retry-After. Pending domains coalesce; a slow or backpressured stream closes rather than accumulating memory. Graceful shutdown drains streams before closing the HTTP server.

The hub is in memory and requires **one API process and one replica**, with jobs and bank sync in that process. Known multiworker settings are rejected at bootstrap, but independent replicas cannot be discovered automatically. Exception: test mode, and the all-mock development verification harness (memory storage and mock AI, bank and push) may set `NODE_APP_INSTANCE=1` to suppress jobs; this does not permit multi-process delivery and explicit multiworker settings remain rejected. Install a shared broker and redesign delivery before scaling. Direct database/admin writes and other processes do not publish; periodic refresh/resume can recover data but does not provide cross-instance realtime. Mobile sleep, disconnected clients, and time-only transitions also require resume or bounded polling. No event replay or exactly-once guarantee is provided.

Caddy retains origin-secret and internal-route guards and explicitly flushes responses; CloudFront and real deployed proxy buffering/timeouts must be verified separately. Heartbeats are designed for the configured 60-second CloudFront read timeout. The automated backend/frontend suites use loopback or mocked dependencies, without dotenv, external providers or database connections. Browser suites additionally use the local `lookwithin_dev` Mongo database with synthetic accounts and mock providers:

```sh
npm --prefix backend run typecheck
npm --prefix backend run test:realtime
npm --prefix frontend run build

```

Browser suites require the externally installed Playwright/browser tooling described in `scripts/browser/README.md`. Start the isolated API with `node -r ./backend/tests/realtime/mock-runtime.cjs --import ./backend/node_modules/tsx/dist/loader.mjs backend/src/server.ts` and Vite with `node frontend/tests/realtime/dev-server.mjs`. These use API port4002, UI5175 and local Mongo only; inspect port ownership first. The preload disables dotenv and real providers, generates temporary signing keys, and disables scheduler jobs. Run browser suites sequentially; repeated synthetic registrations may hit the real local auth limiter (429), in which case wait or restart only the owned mock API. Never disable production rate limiting for tests. Stop the owned API afterward and leave the existing Vite process alone. Browser evidence is local evidence only, not a guarantee for physical devices, CloudFront, or multiworker deployments.

## Verification coordination and comment drafts (2026-11-20)

Equivalent overlapping initial/ready checks share a verification round before advancing the access epoch; explicit access events supersede it. `/me` verification has its own generation/access/meEpoch single-flight, and ordinary refresh joins an equivalent verification. Dirty domains are retained in a Set during verification, with at most two trailing domain passes instead of unbounded full restarts. A round has a20s deadline; `/me` and lock-settings requests have15s deadlines. Existing two automatic retries/backoff and explicit retry remain. Timeout is not logout; late results cannot unmask a superseded round. PIN, offline/resume masking, fresh REST ACL and wallet recovery remain required. A later non-overlapping ready/reconnect can still revalidate; no latency SLA or removal of all checks is claimed. No page reload was added.

Couple story and Friends story/event comment composers write synchronously to best-effort per-tab sessionStorage, with memory fallback. Entries contain text and minimal scope/root IDs only: login generation, user, space, couple, resource kind/id and selected reply root. TTL24h,30 entries,2000 characters each. One active draft destination is retained per resource; selecting another destination explicitly moves that composer text, rather than keeping multiple independent reply drafts. Restore requires matching verified identity, unlocked app and a successful current comment ACL query. Replies re-fetch their exact root before submission; failed target validation never silently posts at the top level. Restored mentions are plain text until selected again.

Successful send clears only its matching revision, so an older response cannot delete newer text. Explicit discard, current403/404, session replacement/logout and confirmed in-session couple replacement purge matching entries; transient errors, bootstrap-null and same-login PIN masks do not. Monotonic bounded handle epochs fence old callbacks after deletion. Off-route resource revocation is discovered when REST access is checked on return, not via a global resource draft index. There is no auto-post/repost and no guarantee of disk persistence when browser storage is disabled/full. This does not preserve other app forms or game composer text across reload.

## Publishing and coverage

Publish after acknowledged writes using `realtimeService.publish(userIds, space, domains, access?)` or the best-effort `realtimeAudience` resolvers. `couple` resolves active couples only; capture previous recipients and send explicit `own` access signals when a relationship is removed. Audience resolution failure drops the hint and never fails a mutation. Private finance and assistant changes must use owner-only delivery unless sharing ACL explicitly permits otherwise. Complex before/after visibility changes require explicit audience capture, not just current-membership resolvers. The hints are deliberately generic, not a replacement for REST authorization.

### Local verification record (2026-11-15)

- Backend: 14 isolated realtime suites passed, including transport/audience, 14 couple cases and 24 finance/assistant scenarios; backend production build/typecheck passed.
- Frontend: realtime parser/cache/auth/lifecycle tests, auth-storage, session-mutations, finance-bootstrap and savings-progress regression scripts passed; production build passed.
- Browser: independent mobile-emulated sessions observed friend acceptance, comments/replies/deletion/reaction; couple mood/check-in; savings proposal/approval/contribution; outing invite/accept/expense/revision and restricted obligations. Known polling intervals were suppressed and actual SSE observed. Ordinary local actions completed in roughly 0.2–1.4 seconds in these samples; this is not a production latency SLA.
- Privacy/drafts: unrelated viewers did not receive private post/outing hints; offline missed revocation was reauthorized, portal drafts survived successful reconnect, forced transient verification failure stayed masked with keyboard retry, and a prepared outing expense retained its draft and received 409 after a remote revision. The session script delivered an old account response after another account logged in and observed no private-data restoration.
- Caddy runtime unavailable locally; Caddy/CloudFront, physical phone/PWA background behavior and distributed/process-crash guarantees were not verified. The legacy full API smoke harness was not run alongside browser verification. Mock suites do not constitute exhaustive coverage of the matrix above.

### Operational and correctness limits

- Dirty hints are sent after known persistence, including known partial writes even if a later operation fails. A rejected operation before persistence should not emit a success hint. For savings and outing money, retain existing locks, CAS, operation IDs, expected revisions and replay/ambiguous-commit reconciliation; never treat an SSE hint as monetary confirmation or silently rebase a prepared operation. Mock tests do not prove real-database concurrency.
- Audience resolution and delivery are best effort and are not atomic with the source write or REST ACL. Membership/block changes can race audience snapshots or hint delivery; generic frames reveal no actor or content, and REST performs the authoritative current check. Notification deletion first snapshots affected owners: concurrent row changes or lookup failure can miss a hint. Polling/resume must recover missed updates; this is not a durable revocation channel.
- The client streams only while foreground, online and authenticated. On access change it masks/removes unsafe cached data and reauthorizes; after offline/resume it keeps sensitive views masked while current access is verified, rather than exposing a stale warm cache. Ordinary dirty events should not remount the app or discard drafts. Polling remains enabled as a fallback, but neither polling nor resume makes multiple process hubs realtime-consistent.
- Local Caddy incremental delivery and deployed Caddy/CloudFront streaming are **not verified** by these tests. After deployment, verify origin-secret and internal-route denies, initial and incremental SSE delivery, heartbeat survival through CloudFront/read timeouts, disconnect cleanup, and no response caching. Do not interpret a local loopback pass as CDN validation.
